LUMIERE · Volumetric RANO Pipeline · Piece 1

Data Loader & Validator — Architecture

A non-destructive fingerprint + conformance pass over longitudinal brain-MRI. Two front doors (LUMIERE now, raw DICOM later) reduce to one internal contract; one validator reports capabilities; a router decides what happens next. Modelled in C4, four levels deep.

Rule 1 — the loader never transforms. It reads, measures, and reports. Resample / skull-strip / register are separate, opt-in, logged stages downstream.
Rule 2 — the validator never rejects. It emits a capability profile; the router maps profile → reject · process · passthrough. Same validator serves both front doors.

Two sources, one system

LUMIERE is preprocessed so its checks pass; a scanner study is raw so the same checks flag deficits and route into processing. The system doesn't branch — the data does.

Segmentation is external

label_schema.py is imported, never re-encoded

Both the label-validity check and the volumetry slice pull region definitions from the single locked source.

ImageRef via ABC in base.py

zip_ref.py is one concrete ImageRef; a future DICOM ref is another. The contract never knows it's a zip.

mask_reference resolves the space trap

The adapter wires an MNI-space reference image beside the mask, so the concordance check compares mask↔reference, never mask↔native-FLAIR.

C4 · L4

Code — the contract types & the check signature

The shapes that harden first. Geometry reads from the NIfTI header only (no full-array load), so fingerprinting stays lazy. Space lives on each ImageRef — the reason the mask-alignment check compares the MNI mask against its MNI reference, never native FLAIR.

# contract/case.py — frozen dataclasses (pydantic stays at the edges)
class SpaceTag(Enum):  NATIVE, MNI152_1MM   # Space(tag, key): two NATIVE keys ≠ co-registered
class Modality(Enum): CT1, T1, T2, FLAIR

@dataclass(frozen=True)
class Geometry:                         # all header-only — no voxels loaded
    shape; spacing; orientation; dtype    # orientation = nib.aff2axcodes(affine)
    anisotropy_ratio; affine              # affine excluded from eq/hash (stays hashable)

class ImageRef(ABC):                      # a LAZY handle, not the array
    geometry  -> Geometry              # cheap: header only
    space     -> Space
    source    -> str                      # provenance
    def load(self) -> LoadedImage       # data + affine + header, on demand

@dataclass(frozen=True, eq=False)
class Timepoint:
    id; label; week_offset
    modalities: dict[Modality, ImageRef]     # raw sequences, native space
    mask; mask_source                            # DeepBraTumIA mask, MNI
    mask_reference; brain_mask                    # MNI images in the mask's own space

@dataclass(frozen=True, eq=False)
class Patient:
    id; timepoints: tuple[Timepoint, ...]   # __post_init__ asserts chronological order

# validate/core.py — every check is a pure function; the runner wraps it so
# an exception becomes a FAIL (loader cannot crash on a bad case).
Check = Callable[[CaseView, Contract], CheckResult]
class CheckResult: status: "pass"|"warn"|"fail"; code; detail; evidence
KEY IDEA

One validator, two verdicts

Why the capability-profile design pays off: the identical check yields opposite — and both correct — verdicts depending on the front door. The router, not the validator, decides what that means.

CheckLUMIERE caseRaw DICOM case
canonical mask presentpass → volumetryabsent → route to segmentation
skull-strippedpassno → route to skull-strip
modalities in one spacediffer (native vs MNI)differ → route to registration
required modality presentpasspass — or genuinely unusable
mask labels ⊆ schemapassn/a (no mask yet)

The trap this avoids

If the validator hardcoded “no mask = unusable”, it could never serve the deployment door. Deficits are data, not rejections.

Single vs multi is the router's job

N == 1 → segment + store. N > 1 → segment + RANO. So the baseline / orderability check only fires when N > 1.

Space-aware alignment

The mask-grid check compares the mask to the image in the mask's space (mask_reference), not native FLAIR — else every LUMIERE case falsely reads "misaligned".

SEQUENCE

Build order — small reviewable steps

Numbered because it is a real dependency chain. Steps 2 and 6 are where we verify against the data rather than assert. ✓ = done and verified.

  1. ✓ Contract + adapter ABCs — contract/case.py · adapters/base.py. Interfaces only; seam smoke-tested.
  2. ✓ LUMIERE adapter — manifest → weeks → zip_ref → adapter. verified: 91 patients / 638 timepoints reconcile with the manifest; ImageRef streams real data.
  3. Fingerprinter — fingerprint/ per-patient record: geometry, spacing, orientation, mask-space, intensity stats, label histograms.
  4. Validator — validate/ checks + CapabilityProfile; runner never raises. Includes the mask↔reference concordance flag.
  5. Router / policy — router/policy.py bucket usable / needs-attention / unusable + N=1 vs N>1 branch.
  6. Volumetry slice — volumetry/volumes.py. verify: reproduce shipped enhancing/edema mm³ for ≥1 patient within rounding.
  7. Tests — synthetic bad cases: missing modality · misaligned mask · off-schema label.
  8. Cohort run + “what surprised us” note — which timepoints fail which check, and how many.
